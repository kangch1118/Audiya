# Audiya

## Overview

- 프로젝트 명:
	Audiya
- 프로젝트 목표:
	사용자의 음악 취향과 감성 요소를 반영하여 맞춤형 플레이리스트를 추천하는 웹서비스를 구현하는 것을 목표로 합니다.
	단순 인기곡 제시가 아니라, 장르/좋아하는 곡/플레이리스트 캡처 이미지/기분/상태/색/계절 데이터를 함께 분석해 개인화 추천 경험을 제공합니다.
	또한 사용자 간 플레이리스트 공유를 통해 취향 교류와 새로운 음악 탐색이 가능한 플랫폼으로 확장하는 것을 지향합니다.
- 프로젝트 기대효과:
	개인 맞춤형 음악 추천 제공, 음악 탐색 편의성 향상, 감성 중심의 차별화된 추천 경험, 사용자 간 취향 공유 활성화, 이미지 기반 입력 기능의 활용성 확대
- 프로젝트 핵심 타겟:
	음악을 자주 듣는 10대 후반~20대, 플레이리스트를 직접 만들거나 공유하는 사용자, 분위기/감정/상황에 따라 음악을 선택하는 사용자

## 프로젝트 내용

사용자의 취향 데이터를 입력받아 맞춤형 플레이리스트를 추천하고, 추천 결과를 공유 가능한 형태로 제공하는 웹사이트 MVP입니다.

- 입력 데이터:
	선호 장르(복수 선택), 좋아하는 곡/가수 텍스트, 플레이리스트 캡처 이미지, 기분/상태/색/계절
- 추천 결과:
	5곡/10곡/15곡 단위 추천
- 결과 분석:
	장르별, 가수별, 국내/해외 비율, 반영 테마 요약
- 공유 기능(초안):
	다른 사용자의 플레이리스트 카드 노출

## 진행 현황

- 1단계(API 연동) 완료:
	추천 시 iTunes 공개 API에서 실시간 곡 데이터를 가져와, 로컬 데이터와 함께 점수 기반 추천에 반영합니다.
	네트워크 이슈가 있어도 로컬 데이터로 추천이 계속 동작하도록 폴백 처리되어 있습니다.
- 2단계(OCR 연동) 완료:
	업로드한 플레이리스트 캡처 이미지에서 Tesseract.js OCR로 텍스트를 추출하고, 추출된 토큰을 추천 점수 계산에 반영합니다.
	OCR 실패 시에는 텍스트 입력 기반 추천으로 자동 폴백됩니다.
- 3단계(공유 저장 백엔드/DB) 완료:
	Node 서버(`server.js`)와 파일 DB(`data/playlists.json`)를 추가해 공유 플레이리스트를 `GET/POST /api/playlists`로 저장/조회할 수 있습니다.
	프론트에서 "현재 추천 공유하기"를 누르면 현재 추천 결과를 DB에 저장하고 목록을 다시 불러옵니다.

## 실행 방법

1. 터미널에서 프로젝트 루트로 이동합니다.
2. Spotify 연동을 사용하려면 환경변수를 설정합니다.
	- `SPOTIFY_CLIENT_ID`
	- `SPOTIFY_CLIENT_SECRET`
	- `SPOTIFY_MATCH_THRESHOLD` (선택, 기본값 `0.34`)
	- `YOUTUBE_API_KEY` (선택, YouTube 후보군 확장)
	- `OPENAI_API_KEY` (선택, 임베딩 기반 AI 재정렬)
	- `OPENAI_EMBED_MODEL` (선택, 기본값 `text-embedding-3-small`)
	- `AI_RERANK_MAX_ITEMS` (선택, 기본값 `60`)
	- 예시는 `.env.example` 참고
3. `npm start`를 실행합니다.
4. 브라우저에서 `http://localhost:3000`을 엽니다.
5. 입력 폼에서 취향/감성 데이터를 선택 후 `추천 받기`를 클릭합니다.
6. 공유 섹션에서 이름/닉네임을 입력하고 `현재 추천 공유하기`를 누르면 DB에 저장됩니다.

## Spotify 공식 API 연동

- 서버 엔드포인트: `GET /api/spotify/playlist?url=...`
- 기능: Spotify 플레이리스트 URL에서 실제 트랙 목록/앨범 이미지/링크를 조회해 추천에 반영
- 주의: Client Credentials 토큰 방식이므로 반드시 서버 환경변수 설정이 필요합니다.
- `.env` 자동 로드 지원: 프로젝트 루트의 `.env` 파일을 서버 시작 시 자동으로 읽습니다.

### 추가 엔드포인트

- `GET /api/spotify/cover?title=...&artist=...`
	- 앨범 이미지가 비어있는 곡에 대해 Spotify 검색으로 커버/링크를 보강합니다.
- `GET /api/spotify/candidates?terms=...&origin=...&limit=...`
	- 다중 검색어 + 페이지네이션으로 넓은 Spotify 후보군을 수집해 추천 풀을 확장합니다.
- `GET /api/youtube/candidates?terms=...&origin=...&limit=...`
	- YouTube Data API(v3)로 음악 카테고리 후보군을 추가 수집해 곡수 부족 상황을 줄입니다.
- `POST /api/ai/rerank`
	- 추천 후보를 임베딩 유사도 기반으로 재정렬합니다.
	- `OPENAI_API_KEY`가 없으면 서버 내 로컬 의미 기반 재정렬로 자동 폴백합니다.

## 멀티 소스 전략

- 현재 추천 풀은 `Spotify + iTunes + YouTube + 로컬`을 합쳐서 구성됩니다.
- 중복 제거(제목+아티스트), 장르/국내외 하드 필터, 점수 정렬을 통해 멀티 소스 혼선을 최소화합니다.
- 참고: Apple Music 공식 API는 JWT 기반의 개발자 토큰 발급/관리 절차가 필요해 MVP에서는 `iTunes Search API`를 Apple 카탈로그 대체 소스로 사용합니다.

### 매칭 임계치 튜닝

- `SPOTIFY_MATCH_THRESHOLD` 값으로 Spotify 매칭 엄격도를 조정할 수 있습니다.
- 권장 범위: `0.25 ~ 0.50`
	- 낮을수록 더 많이 매칭되지만 오탐 가능성이 올라갑니다.
	- 높을수록 정확하지만 커버가 비어 있을 확률이 올라갑니다.

## 파일 구성

- `index.html`: 페이지 구조 (Overview, 입력 폼, 추천 결과, 분석, 공유 섹션)
- `styles.css`: UI 스타일, 반응형 레이아웃, 카드/칩 디자인
- `app.js`: 점수 기반 추천 로직, 결과 렌더링, 분석 요약 생성
- `server.js`: 정적 파일 서빙 + 공유 플레이리스트 API
- `data/playlists.json`: 공유 플레이리스트 저장 파일 DB
